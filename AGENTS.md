# antrel-os: контекст для агента

Этот файл читается агентом (omp) автоматически при запуске в `~/antrel-os`.
Описание системы, структура репозитория и установка — в `README.md`; здесь то, чего в README нет: кто
пользователь, как с ним работать, почему приняты решения и что делать дальше.

## Пользователь

- Antrel, пишет по-русски; отвечать по-русски, просто, без жаргона. Не эксперт в Linux.
- Цель: красивая, удобная, стабильная система вместо Windows, которая переустанавливается одной командой в
  то же самое состояние. Windows остаётся рядом (dual-boot).
- Хочет минимум возни: готовые решения, а не написанные с нуля; дизайн — свой, не копия Windows/macOS.
- **Решения обсуждаются по шагам.** Не забегать вперёд: большие изменения (новый слой системы, замена
  компонента, разметка диска) — только после явного согласия.
- Мелкие правки, исправления, ведение репозитория — на агенте без отдельного согласования.
- Агент отвечает за репозиторий целиком: коммиты, теги, README, этот файл.

## История: почему начали заново

NixOS → Fedora → Arch + Hyprland сменили друг друга, и ни одна система так и не была запущена на железе;
пользователь запутался. Решили начать с простой базы: Arch + KDE Plasma, поставить её, запустить агента
внутри и настраивать систему уже оттуда, по шагам. Прошлые состояния — теги `nixos-archive`,
`fedora-archive`, `arch-hyprland-wip` (там готовый базовый `hyprland.lua` и waybar, если вернёмся к Hyprland).

## Главная обязанность: репозиторий = текущая система

Всё, что меняется в системе, должно оказаться в репозитории:

| Что изменилось | Куда записать |
|---|---|
| Поставили программу через pacman | `packages/pacman.txt` |
| Поменяли системный файл в `/etc` (или другой вне `~`) | положить его в `system/` по тому же пути |
| Настройка программы в `~/.config` | если папка уже в `links.txt` — просто коммит; если нет — `./track.sh ~/.config/<папка>` и коммит |
| Разовое действие, которое нельзя описать файлом | шаг в `setup.sh`, повторный запуск должен быть безопасен |

- Перед коммитом смотреть `git status` и `git diff`; коммитить осмысленными порциями.
- **Репозиторий публичный — личное не коммитить.** Секреты не трекать никогда: `~/.config/gh`, настройки
  Happ (ссылка подписки VPN), профили браузера, ключи, токены, кэш. Перед `track.sh` проверить, что в папке нет
  секретов и мусора.
- KDE хранит настройки отдельными файлами прямо в `~/.config` (`kdeglobals`, `kwinrc`, `kxkbrc`…) и
  перезаписывает их целиком. `track.sh` рассчитан на папки; как держать под git настройки KDE — решить, когда
  дойдёт очередь (проверить, не рвёт ли KDE ссылку на файл при сохранении).
- `sudo` агент не знает: команды с `sudo` (включая `sudo ~/antrel-os/setup.sh`) просит выполнить пользователя.

## Ключевые решения и почему

| Решение | Почему |
|---|---|
| Arch, только официальные репозитории | Hyprland (возможная цель) там родной; в Fedora его пакет удалён, остаётся COPR одного человека. AUR запрещён: волны вредоносных пакетов в 2026. Не из репозиториев: Happ (`.pkg.tar.zst` производителя), omp (скрипт установки) |
| KDE Plasma как база | готовый полноценный рабочий стол без настройки; на нём удобно настраивать всё остальное. Смена на Hyprland — отдельное решение пользователя |
| Свой `install.sh`, а не archinstall | простое меню выбора места: все диски полосками, варианты «свободное место» (только GPT, от 30 ГБ), «переустановить antrel-os», «стереть диск» (подтверждается именем диска). Флешка и смонтированные диски не предлагаются. GRUB — в EFI-раздел того же диска (Windows, если есть), иначе создаётся свой на 1 ГБ. Ничего, кроме выбранного места, не трогает. Консоль флешки — 8 цветов и символы CP437 (`√`, `►`, `█`, `░`; `✓` там нет) |
| btrfs `@`, `@home`, `compress=zstd:1` | основа для будущих снимков с откатом (snapper) |
| GRUB в текстовом режиме, `os-prober` | графический GRUB зависал на этой X99 (NixOS, nixpkgs#427235); EFI-раздел Windows всего 196 МБ, поэтому ядра на btrfs, а на EFI только GRUB |
| `nvidia-open` + mkinitcpio без хука `kms` | готовые открытые модули для RTX 3070 под стандартное ядро; без `kms` nouveau не попадает в initramfs |
| Plasma Login Manager (`plasmalogin.service`) | экран входа, который KDE ставит сам: входит в `plasma-meta` (Plasma 6.8). SDDM не нужен |
| zram (половина RAM) | подкачка без отдельного раздела |
| Вес CPU сессии (`user-<uid>.slice`, пишет `setup.sh`) | сессия пользователя важнее фоновых служб |
| Зеркала: `reflector` по BY, LT, LV, PL, DE, FI, SE | в Беларуси мало зеркал; быстрейшие из соседних |
| Happ: копия ярлыка с `QT_QPA_PLATFORM=xcb` | встроенный в Happ Qt Wayland падал (на Hyprland); на KDE не проверено — можно убрать, если без него работает |
| Шрифты: subpixel RGB, hintslight, stem darkening | пользователя раздражали тонкие/мыльные шрифты; при мыле — `hintfull` |
| Настройки — ссылками из `home/` (`links.txt`, `track.sh`) | правки сразу попадают в git; ссылки на целые папки |
| `setup.sh`: вывод на английском, части независимы | каждая часть (`part`) и элемент (`item`) в отдельной подоболочке; ошибка помечает часть, остальное идёт дальше, в конце список и код 1. Новые шаги добавлять так же |
| Репозиторий публичный | установка одной командой без входа в GitHub |

## Правила работы с репозиторием

- Conventional Commits (`feat(kde): …`, `fix(audio): …`), один коммит — одно логическое изменение,
  тело коммита — список изменений.
- После правки скриптов: `shellcheck install.sh setup.sh track.sh`; `setup.sh` — прогон в контейнере
  `archlinux` (пользователь с uid 1000, `sudo bash setup.sh --yes`, затем повторный прогон без ошибок).
- Стабильные состояния — теги `vX.Y`. `v0.1` — первая удачная установка.

## Чек-лист после первой загрузки

1. Видеокарта: `lspci -k | grep -EA3 'VGA|3D|Display'` → драйвер `nvidia`; `nvidia-smi` работает.
2. Сессия: `echo $XDG_SESSION_TYPE` → `wayland`, KDE работает плавно.
3. Мониторы: оба на родном разрешении, расставить (Параметры системы → Экран).
4. Windows в меню GRUB. Если нет: `sudo grub-mkconfig -o /boot/grub/grub.cfg`.
5. Раскладка us/ru (Параметры → Клавиатура), чувствительность мыши как в Windows (ускорение выключено) —
   вместе с пользователем; решить, как хранить эти настройки KDE в репозитории.
6. `gh auth login`, `git push` из `~/antrel-os` работает.
7. Happ: подписка, подключение; если работает без XWayland — убрать обход из `setup.sh`.
8. Звук: MiniFuse 1 выходом по умолчанию.
9. Шрифты: сравнить с Windows на том же мониторе.
10. Всё работает → тег `v0.1`.

## Дальше (обсуждать по одному)

- Внешний вид: остаться на KDE и оформить его или перейти на Hyprland (см. `docs/design/`, тег `arch-hyprland-wip`).
- Установщик станет основным способом ставить систему: сделать его красивым, с «вау-эффектом» прямо в консоли
  флешки (своя палитра из 16 цветов через `\e]P…`, крупный шрифт `setfont`, анимации, полоски прогресса),
  не теряя надёжности.
- Снимки btrfs с откатом из меню загрузки (snapper + grub-btrfs).
- Отзывчивость под нагрузкой: `scx_bpfland` (`scx-scheds`), если интерфейс будет подтормаживать.
- Программы с Windows: Unity Hub (главное), Telegram, Steam, Blender, Krita, VS Code и др.
- В Windows отключена защита системы (точки восстановления) ради сжатия диска; можно включить обратно.

## Где остановились (2026-11-28, разговор из Windows)

Установка на железе прошла, GRUB работает. Пользователь не смог войти «в аккаунт» на Arch — сначала выяснить,
что именно: экран входа KDE не принимает пароль (тогда это ошибка установки, чинить первой) или GitHub/Happ.

Решено:
- **Название ОС меняем** (`antrel-os` звучит странно). Окончательное ещё не выбрано, думаем дальше.
  Настроение — референс: дождливый вечер, тёплые фонари, lo-fi. Обсуждали: serein, rainyplace, evenfall,
  lamplit, amaya — ни одно не утверждено. Переименование затронет репозиторий на GitHub, команду установки,
  метку раздела (установщик должен узнавать и старую `antrel-os`), GRUB, имена файлов, `~/antrel-os`.
- **Лицензия: GPL-3.0** (пользователю важно, чтобы было открытым; версии на основе обязаны оставаться открытыми,
  сохранять авторство и помечать изменения). Добавить `LICENSE` и строку об авторстве в README.
- **Уборка следов прошлых попыток:**
  - убрать упоминания NixOS/Fedora/Hyprland/43PR из README, AGENTS.md, скриптов и код для Fedora в
    `install.sh` (`clean_esp`); факты о железе оставить (графический GRUB зависает на этой X99);
  - удалить метки `nixos-archive` и `fedora-archive` (их коммиты и так в истории main);
  - метку `arch-hyprland-wip` **оставить** (там единственная копия работы над Hyprland);
  - убрать `docs/design/reference-01-floating-pills.png` (чужой скриншот с чужими обоями, публиковать нельзя),
    словесное описание стиля оставить.
- **Новая история:** начать репозиторий заново в новой ветке без старой истории (orphan). Когда она станет
  самостоятельной, заменить ею `main`. Сначала договориться о названии — ветку логично начать уже с ним.

Следующие темы, по порядку: название → меню загрузки (почистить текстовый GRUB: только «ОС» и «Windows», свои
цвета; заставка Plymouth; на пробу rEFInd отдельным пунктом) → красивый установщик (палитра `\e]P`, `setfont`,
логотип, полоски этапов, шумный вывод только в журнал) → установка в два этапа: основа в установщике,
тяжёлые программы (Steam, Unity Hub, Blender…) фоновой службой после первого входа с низким приоритетом.
Открытые вопросы там: разрешить ли Flatpak/Flathub (Unity Hub официально — AppImage/Flatpak; Unity пишет, что
вход в Hub на Arch может не работать — проверить первым), `multilib` для Steam.
