# antrel-os: контекст для агента

Этот файл читается агентом (omp) автоматически при запуске в `~/antrel-os`.
Описание системы, структура, горячие клавиши и установка — в `README.md`; здесь то, чего в README нет:
кто пользователь, как с ним работать, почему приняты решения и что делать дальше.

## Пользователь

- Antrel, пишет по-русски; отвечать по-русски, просто, без жаргона. Не эксперт в Linux.
- Цель: красивая, удобная, не захламляющаяся система вместо Windows. Windows остаётся рядом (dual-boot).
- **Решения обсуждаются по шагам.** Не забегать вперёд: большие изменения (новый слой системы, замена
  компонента, разметка диска) — только после явного согласия. Однажды агент начал писать конфиг до конца
  обсуждения, и пользователь его остановил.
- Мелкие правки, исправления, ведение репозитория — на агенте без отдельного согласования.
- Предпочитает готовые решения написанию с нуля; дизайн — свой, не копия Windows/macOS.
- Агент отвечает за репозиторий целиком: коммиты, теги, README, этот файл.

## Ключевые решения и почему

| Решение | Почему |
|---|---|
| NixOS, ветка unstable | вся система в git; агент правит конфиг, а не живую систему; откат из меню GRUB. Unstable — ради свежих Hyprland и Dux Shell |
| Hyprland, конфиг на **Lua** (`home/antrel/hyprland.lua`) | гибкость внешнего вида. С 0.55 hyprlang устарел; API — `hl.config`, `hl.bind`, `hl.dsp.*` (см. wiki.hypr.land и `example/hyprland.lua` в репозитории Hyprland) |
| Dux Shell (бывш. DankMaterialShell, `programs.dux-shell`) + `dux-greeter` | готовая красивая оболочка с официальной поддержкой NixOS. Запасной вариант — Noctalia (`programs.noctalia` в nixpkgs). Модуль не пишет конфиг Hyprland: бинды на IPC (`dms ipc call …`) — в `hyprland.lua` |
| Без GNOME и запасной сессии | экономия места на 40 ГБ; страховка — Windows и откат поколений |
| UWSM (`programs.hyprland.withUWSM`) | Hyprland как systemd-сессия: `graphical-session.target` запускает `dms.service` |
| GRUB, ядра на btrfs | общий EFI-раздел Windows всего 196 МБ (свободно ~144 МБ) — для поколений NixOS мало |
| Раздел 40 ГБ, btrfs `@`, `@home`, `@nix`, zstd | больше Windows не отдала (файл подкачки мешал сжатию). Расширять — через `btrfs device add` второго раздела |
| `scx_bpfland`, nix-daemon с приоритетом idle, `max-jobs=4`/`cores=7`, вес CPU сессии | на Fedora интерфейс лагал под нагрузкой (Xeon с медленными ядрами + GNOME/NVIDIA) |
| NVIDIA, `open = true` | RTX 3070 «Frankenstein» (мобильный GA104) работала на Fedora с akmod-nvidia. Если открытые модули не взлетят — `open = false` |
| Шрифты: subpixel RGB, hinting slight, stem darkening, GTK4 `font-rendering=manual` | пользователя раздражали тонкие/мыльные шрифты Linux. Следующий шаг при мыле — `hinting.style = "full"`; подбирать на живом мониторе |
| Happ — своя сборка `.deb` (`pkgs/happ`, версия зафиксирована), запуск через XWayland | VPN (Беларусь): без него не работают сервисы моделей для omp. Встроенный Qt Wayland Happ падает на Hyprland |
| omp — flake `github:can1357/oh-my-pi` без `follows` | собирается так, как его тестирует автор |
| Бинды как в Windows (Win, Win+E/L/V/I/A/N/X/Tab, Alt+Tab, Alt+F4, Win+Shift+S, Ctrl+Shift+Esc) | привычки пользователя: на основном мониторе одно окно на весь экран, Alt+Tab между окнами |
| Репозиторий публичный | установка одной командой без входа в GitHub. Секретов в репозитории нет и быть не должно |

## Правила работы с репозиторием

- Conventional Commits (`feat(hyprland): …`, `fix(audio): …`, `chore(flake): update …`), один коммит —
  одно логическое изменение, тело коммита — список изменений.
- Перед коммитом изменение собирается: `nixos-rebuild build --flake .#uiux-2680` (без sudo, ничего
  не активирует). Применяет пользователь: `sudo nixos-rebuild switch --flake .#uiux-2680` — агент не
  знает пароль sudo, поэтому просит пользователя выполнить команду.
- Ошибки конфига Hyprland после применения: `hyprctl configerrors`; перечитать конфиг — `hyprctl reload`.
- `flake.lock` обновляется отдельным коммитом. Happ обновляется осознанно: `version` + хеш через
  `nix store prefetch-file <url>`.
- Стабильные состояния — теги `vX.Y`. `v0.1` — первая удачная установка (ещё не поставлен).
- Пароли, токены, ссылки подписки VPN в репозиторий не попадают никогда.

## Состояние на момент установки

Проверено до установки (в Docker на Windows): система вычисляется без ошибок и предупреждений, Happ
собирается, Hyprland принимает `hyprland.lua`, `install.sh` проходит `shellcheck` и все проверки разметки
на виртуальном диске. **Не проверено на железе ничего** — это задача первой загрузки.

## Чек-лист после первой загрузки

1. Видеокарта: `lspci -k | grep -EA3 'VGA|3D|Display'` → драйвер `nvidia`; `nvidia-smi` работает.
2. Сверить `~/hardware-generated.nix` (создан `install.sh`) с `hosts/uiux-2680/hardware.nix`, перенести
   отличия, удалить файл.
3. Мониторы: оба на родном разрешении, масштаб 1; расставить слева/справа (`hl.monitor` по именам
   выходов из `hyprctl monitors`).
4. `gh auth login`, затем убедиться, что `git push` работает.
5. Dux Shell: панель сверху в стиле `docs/design/reference-01-floating-pills.png` (отдельные «таблетки»
   без фона). Не получается настройками — обсудить Noctalia или точечную доработку.
6. Happ: запускается, подписка импортируется, TUN-режим поднимает `tun0`.
7. Отзывчивость: `systemctl status scx_loader`; нагрузка
   `nix-shell -p stress-ng --run 'stress-ng --cpu 28 -t 60'` и одновременно двигать окна — рывков быть не должно.
8. Шрифты: сравнить с Windows на том же мониторе, подстроить hinting.
9. Звук: MiniFuse 1 выбирается выходом по умолчанию.
10. Спросить, удобен ли Alt+Tab и остальные бинды.
11. Всё работает → тег `v0.1`.

## Отложено (обсудить с пользователем, когда дойдёт очередь)

- Программы с Windows: Unity Hub (главное), Telegram, Discord, Steam, Blender, Krita, VS Code и др.;
  замены для Windows-only (КОМПАС, Equalizer APO, Lossless Scaling, Wallpaper Engine).
- Анимированные обои: `linux-wallpaperengine` (работает на Hyprland) или видео-обои Dux Shell.
- Impermanence (чистый корень при каждой загрузке) — идея против «помойки», не включать без обсуждения.
- Секреты в репозитории (если понадобятся) — только через sops-nix.
- В Windows отключена защита системы (точки восстановления) ради сжатия диска; можно включить обратно.
